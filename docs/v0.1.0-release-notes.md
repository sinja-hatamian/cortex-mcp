# Cortex MCP v0.1.0

Cortex MCP is an experimental, local-first MCP server for recording verification criteria, evidence provenance, assumptions, and deterministic review findings. It runs over stdio and stores project records and review snapshots in SQLite.

## What's included

| Tool                       | Purpose                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------- |
| `cortex_create_claim`      | Register a claim with explicit verification criteria.                                 |
| `cortex_add_evidence`      | Attach evidence to a claim or criterion and record its claimed origin.                |
| `cortex_track_assumption`  | Record a working assumption as unverified.                                            |
| `cortex_update_assumption` | Update an assumption and record the reason in its history.                            |
| `cortex_review`            | Evaluate a claim or get an advisory decision recommendation under the project policy. |
| `cortex_get_context`       | Recover recent claims, evidence, assumptions, history, and review summaries.          |

The CLI also provides `cortex_health` for checking the connection.

## Install and try it

Build from source with Node.js `26.13.0` and pnpm `12.16.1`.

```sh
git clone https://github.com/sinja-hatamian/cortex-mcp.git
cd cortex-mcp
git checkout --detach 6dfef47b7aaf6acd6268c009a9c6a811617d3353
pnpm install --frozen-lockfile
pnpm build
```

Configure your MCP client to run `node` with the absolute path to `dist/cli.js`. Dependency installation uses the npm registry. After installation, the server runs without network access, an account, or an API key. [Client configuration and storage paths](https://github.com/sinja-hatamian/cortex-mcp/blob/6dfef47b7aaf6acd6268c009a9c6a811617d3353/README.md#connect-a-client)

Run `pnpm smoke:auth` to see a missing-evidence warning, a claim that stays unverified after the caller reports full coverage, and an advisory blocked recommendation for a refuted assumption. The example also verifies that context survives reconnecting. [Authentication example](https://github.com/sinja-hatamian/cortex-mcp/blob/6dfef47b7aaf6acd6268c009a9c6a811617d3353/examples/authentication-verification.md)

## Evidence and assurance

- Under the default strict policy, `unverified` means the criteria lack admissible support. The result reports caller-reported coverage separately.
- Under a configured provisional policy, `verified` with `assurance: "provisional"` means the criteria were satisfied by records that policy admits. Their origins are supplied by the caller and are unauthenticated.
- Decision recommendations are advisory. Project IDs scope records within a local database and provide logical separation. [Security and trust](https://github.com/sinja-hatamian/cortex-mcp/blob/6dfef47b7aaf6acd6268c009a9c6a811617d3353/SECURITY.md)
